# SSH Gate 安全模型

本文描述 **1.0.0 基线**下 SSH Gate 的安全边界和明确不提供的保证。

## 1. 信任边界

SSH Gate 假设：

- Windows 当前用户和本机 SSH 配置由用户控制。
- 远端服务器输出、文件名和文件内容均不可信。
- ChatGPT / MCP 调用方可以请求操作，但不能自行获得本地审批权。
- OpenAI Secure MCP Tunnel 负责受支持的远程连接路径；SSH Gate 不自行开放公网端口。

本项目不是远端主机沙箱，也不是 Windows 终端安全产品。它的目标是缩小可远程调用能力，并把敏感确认留在本机。

本地终端面板是给坐在本机前的用户使用的普通 PowerShell，以当前 Windows 用户权限运行，不受审批或自动只读策略约束。它只通过带能力令牌的 WebView 桥访问，MCP 无法读写这个面板；输入输出只保存在内存中，不写入审计、日志或配置。

MCP 使用本机需要另行登记“本机工作区”（`kind: "local"`，`workspace_roots` 列出 1–8 个目录），它和 SSH 服务器一样走请求、审批和审计流程：

- **文件操作**（浏览、属性、读取、搜索、上传、下载、会话目录）在执行时把路径解析到真实位置，符号链接和目录联接都会被跟随，真实位置必须仍在工作区真实目录内。遍历时不进入链接和联接。设备名、`\\?\` 前缀、备用数据流和以点或空格结尾的名称在提交时即被拒绝。上传只写入新文件，或在显式选择覆盖时替换普通文件；目录 ZIP 只解压到新目录。
- **命令**是 PowerShell 脚本，在新进程中从工作目录启动，使用 `-NoProfile`，并清除启动器的 Python 环境变量。PowerShell 能访问当前用户可访问的任何路径，工作区不构成命令的沙箱，因此每条本机命令都需要人工审批：只读开关和临时授权都不适用。审批界面显示实际执行的完整脚本和 PowerShell 路径。命令运行在 Windows 作业对象中，结束、终止或超时时会清理它启动的整个进程树（已脱离作业的进程除外）。

## 2. 本地审批

MCP 不暴露“批准请求”“修改授权策略”“录入密码”“接受新指纹”等工具。

需要人工确认的请求必须经过 WebView 内的本地桥接。审批票据：

- 与具体请求 ID 和摘要绑定；
- 有有效期；
- 只能使用一次；
- 请求内容变化后不能复用旧票据。

前端的按住确认只是一层误触保护；真正的请求一致性校验在后端完成。

人工审批默认 60 秒到期，最长 60 秒；旧配置的更长期限在加载时收敛。批准按钮需按住 0.5 秒，放开、离开按钮、切换请求、失焦或隐藏窗口都会取消尚未完成的按住。主界面按 A 立即批准审批栏最上面一条（带 A 标记）；焦点在输入框、本地终端、对话框、抽屉或命令面板中时不响应。按钮倒计时从右向左消退，按住进度从左向右增加。过期是否可执行由后端再次判定。

### 临时授权

`request_auto_approval` 创建授权申请，不授予调用方本地审批权，也不修改永久策略。只有已有的本地预授权范围或一次本地审批可以创建进程内 `grant_id`。申请工具会诚实标记为会改变本地状态；工具注解不承担权限检查，也不改变 ChatGPT 平台的确认设置。

授权绑定服务器及有效 SSH 配置、绝对目录、能力、完整固定命令或限定 Git 参数、期限、次数和单次超时。默认最多 30 分钟、50 次、单次 300 秒；人工批准上限为 1 小时、100 次，执行时限还受全局上限约束。固定命令完整匹配，不按前缀或风险分数放行。

- 只读预授权不能隐式扩大成 pytest、Git 写入或任意程序执行。
- `python_tests`、`git_deploy_pull` 必须在本地显式预授权且设置目录；自动部署限定 `origin/main`。`manual_only` 不产生免审批授权。
- `git_full` 和 `exact_commands` 始终需要一次本地批准；shell 组合、包装和内联程序仍逐次审批。
- 授权计数在实际派发前消耗；派发失败也消耗，完全相同请求的重试不消耗第二次。
- 排队启动、SSH 检查后和发出执行命令前再次校验授权。撤销、过期、配置变化或应用重启后拒绝新执行；关闭自动放行撤销当前授权。
- 撤销取消排队工作，不自动终止已经运行的工作。后者使用 `terminate_command`。

MCP 调用方没有可信的对话身份；不接受自报 chat ID 作为隔离凭据。授权属于当前 SSH Gate 进程，持有授权 ID 的同一连接调用方可以在范围内使用。需要跨用户隔离时应使用独立进程或另行提供可信认证边界。

## 3. 自动只读准入

自动授权基于解析后的 argv、操作类别和路径范围，不按字符串关键词简单放行。

明确不会自动按只读执行的典型情况：

- shell 管道、重定向、多命令组合和替换；
- `find -delete/-exec/-execdir/-fprint`；
- Git 写操作和外部 diff/textconv/output 行为；
- Docker restart/exec/build/cp 等写操作；
- 未识别选项或无法可靠解析的脚本。

`python_tests` 是显式信任类别。pytest 会执行项目代码，因此即使命令形式受限，也不能把它视为操作系统意义上的只读。

有目录范围时，文件命令检查路径操作数、`grep -f/--file` 和 `find -newer` 中的路径，并核验 SFTP 返回的真实路径。拒绝 find/grep/du 的递归符号链接跟随选项。检查仍不是 OS 沙箱，不能消除远端并发文件修改的竞态。

### Git 远端

`inspect_repository` 读取生效的 fetch/push URL（含 `insteadOf/pushInsteadOf` 改写），解析简单 SSH Host/HostName 别名，返回主机和类型，不返回 URL 凭据。含 Include/Match、无法解析的 SSH 别名或混合远端会要求核对；本地 `github_hosts` 可明确登记 GitHub Enterprise 主机或 GitHub 别名。

受支持的直接 Git 命令在执行前重复核验远端。GitHub 服务器副本仅受限检查和指定远端的 fetch/快进 pull；代码开发使用 GitHub 工具。首次部署使用 `bootstrap_repository` 时只接受已确认的 GitHub URL 和空/不存在的规范化绝对目标路径，并可绑定完整提交 SHA。该流程关闭仓库 hooks/fsmonitor，并通过 `GIT_CONFIG_NOSYSTEM=1` 与 `GIT_CONFIG_GLOBAL=/dev/null` 阻止 system/global Git 配置把 URL 重写到另一远端；SSH `Host`/`ProxyJump` 配置仍由 OpenSSH 处理。非 GitHub 远端确认后才接受 `git_full`，仍拒绝自动强制推送、删除分支、rebase exec 等选项。固定执行路径关闭 hooks、fsmonitor、pager、外部 diff 和 textconv；Git 全局路径/配置覆盖和组合命令不作为直接 Git 操作执行。

远端账号配置和经本地批准的项目程序必须可信。任意脚本、Git filter、测试或构建程序可能调用 Git 或修改目录外资源；这里的直接 Git 策略不声称拦截其内部行为。真正限制这些副作用需要远端容器、账号和 OS 权限隔离。

## 4. SSH 主机身份

- 已知主机按 `known_hosts` 校验。
- 未知主机在本地展示 SHA256 指纹，由用户选择仅本次信任或保存。
- 指纹不匹配直接失败，不提供“忽略并继续”的远程接口。
- ProxyJump 链的每一跳独立校验。

前端指纹图只用于辅助辨认，完整 SHA256 文本才是核验依据。

## 5. 凭据存储

当前 `CredentialStore` 使用 AES-256-GCM：

- 每条记录使用随机 96-bit nonce；
- 使用稳定的 opaque reference 作为 AAD；
- 主密钥为随机 256-bit 数据；
- 密文和主密钥默认分离存放。

不会写入 `config.json` 的内容包括：

- SSH 密码
- 私钥口令
- 选择记住的 Tunnel Runtime API Key

运行中的秘密不会出现在 MCP 快照、命令行参数或审计日志中。认证失败导致已保存凭据失效时，相关记录会清除并重新要求本地输入。

### 当前限制

`FileKeyProvider` 主要防止把源码目录、配置文件或日志误提交后直接泄露明文。拥有当前 Windows 用户文件读取权限的攻击者仍可能同时获得密文与主密钥。若需要更强的本机隔离，应实现 Windows DPAPI / Credential Manager 等系统级 `KeyProvider`。

## 6. 私钥与 SSH agent

- 私钥文件始终从本机读取，不上传到跳板。
- 私钥口令只在本地输入。
- `IdentitiesOnly yes` 会限制尝试身份。
- 不启用 agent forwarding。
- 跳板只承担 SSH channel 转发，不会接收到目标机 shell 命令。

## 7. 命令执行

远端命令按已审批的字面脚本执行，SSH Gate 不提供隐藏脚本、编码后执行或远程修改审批摘要的机制。

命令终止采用远端进程组验证。以下情况不保证被终止：

- 程序自行 `setsid` / daemonize；
- 提交给 Docker daemon、systemd、队列系统等其他管理器的后台任务；
- 网络中断使清理过程无法确认。

因此调用方必须检查终止确认结果，而不是把 terminate API 返回本身当成最终成功。

## 8. 文件系统与 SFTP

结构化文件工具避免用 shell 拼接任意文件路径。路径和 ZIP 内容会做边界校验，包括：

- 绝对路径/根目录范围检查；
- 最终符号链接与目录符号链接限制；
- ZIP traversal、绝对路径、符号链接、重复成员、加密成员与异常展开拒绝；
- 上传大小和 SHA256 校验；
- 默认不覆盖远端文件。

传输缓存本身可能含有真实敏感文件，使用完成后应清理。

## 9. Tunnel 与代理

MCP 和 Tunnel 只使用回环地址连接。代理配置仅影响 Tunnel 云控制面/下载链路，并明确设置本地地址绕过代理。

手动持久配置拒绝带 userinfo 的代理 URL。确需代理认证时，可以在启动应用前通过受支持的本机环境变量提供；界面、日志和快照应隐藏认证信息。

HTTPS 诊断始终校验证书，没有“跳过 TLS 校验”的选项。

## 10. 日志与审计

`logs/audit.jsonl` 用于记录：

- request ID
- 请求摘要
- 状态变化
- 自动/人工准入类型
- 终止相关事件

它不应记录密码、私钥内容、API Key、完整命令或完整命令输出。`get_command_history` 为中断恢复返回当前进程内存中的原始命令/结构化参数，但这些内容不会写回 `audit.jsonl`，应用重启后也不会从审计日志恢复。调用方仍不应把凭据放进命令参数。日志目录仍属于本地敏感数据，应按普通运维日志处理。

## 11. 不提供的保证

SSH Gate 1.0.0 不承诺：

- 对已被入侵的 Windows 用户环境保护凭据；
- 把远端 Linux 账号限制成真正的 OS 沙箱；
- 可靠终止已经逃离原进程组的后台工作；
- 从浏览器 UI 还原 stdout/stderr 的真实微秒级交错顺序；
- 用 `/readyz` 证明 ChatGPT 工作区权限或插件授权一定正确。
